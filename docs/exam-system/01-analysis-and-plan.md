## 1. ما الذي تم فحصه؟

| البند | الوضع الحالي |
|---|---|
| **التقنيات** | Next.js 15 (App Router) + React 19 + TypeScript + Tailwind 4، و Prisma 6 للوصول إلى قاعدة البيانات، و zod للتحقق، و bcryptjs و jose للجلسات، و framer-motion للحركة. |
| **قاعدة البيانات** | PostgreSQL على Supabase (مشروع `rbxtixmrlfvsdrjxihpf`، منطقة eu-west-1). الاتصال من الخادم بمستخدم مخصص `daleel_app` يملك الجداول. |
| **الجداول الحالية** | User, AuditLog, Program, CourseSession, Registration, ConsultingService, ConsultationRequest, CorporateRequest, ContactMessage, Resource, Favorite, Credential, Testimonial, Stat, Faq, Subscriber, Media, Setting, Notification. |
| **العلاقات** | Program ← CourseSession و Registration. و User ← Registration (اختيارية: `userId`) و Favorite و AuditLog. و Resource ← Favorite. |
| **نظام الدورات** | جدول `Program` (10 برامج حاليًا: PMP, CAPM, RMP, ACP …) مع `CourseSession` للمواعيد. كل دورة لها `id` و `slug` و `code`. |
| **تسجيل المتدربين** | جدول `Registration` هو **طلب تسجيل** (اسم، بريد، هاتف، حالة: NEW / CONTACTED / CONFIRMED …) وليس قيدًا فعليًا. الحقل `userId` موجود لكنه غير مستخدم بعد. **لا يوجد نظام "قيد" (Enrollment) يربط حساب المتدرب بالدورة.** |
| **المستخدمون والأدوار** | جدول `User` بأدوار: `ADMIN` و `EDITOR` و `LEARNER`. **لا يوجد دور "مدرب"** ولا ربط بين مستخدم ودورة. |
| **تسجيل الدخول** | نظامان: (1) في النسخة الكاملة (الخادم): جلسات موقّعة بـ jose مع كلمات مرور bcrypt في جدول `User`. (2) في الموقع المنشور (GitHub Pages): حسابات المتدربين عبر **Supabase Auth** (جدول `auth.users` منفصل عن `User`). **الحسابان غير مرتبطين حاليًا.** |
| **لوحة المدير** | `/admin` على الخادم المحلي فقط: المحتوى، صندوق الطلبات، الوسائط، المشتركون، الإعدادات، سجل التدقيق، النسخ الاحتياطي، الملف الشخصي. |
| **لوحة المتدرب** | صفحة `/account`: المفضلة والملف. لا دورات ولا اختبارات. |
| **لوحة المدرب** | غير موجودة. |
| **نظام المحتوى** | يُدار من لوحة المدير ويُحفظ في قاعدة البيانات. الموقع المنشور يُبنى منه كصفحات ثابتة. |
| **الملفات والتخزين** | الرفع إلى مجلد `uploads/` على جهاز الخادم. للنشر تُنسخ إلى `published-uploads/` ثم تصبح **روابط عامة**. لا يُستخدم Supabase Storage. |
| **الدفع** | غير موجود. |
| **البناء والنشر** | GitHub Actions يبني الموقع كـ **ملفات ثابتة** (static export) وينشره على GitHub Pages، عند كل رفع وكل يوم الساعة 01:00 UTC. السكربت `scripts/prepare-static.mjs` يحذف قبل البناء لوحة المدير وواجهات API والإجراءات التي تحتاج خادمًا. |
| **الخدمات الخارجية** | Supabase (قاعدة البيانات + Auth)، GitHub Pages، SMTP اختياري، Google Analytics اختياري. |
| **الأمان** | في Supabase: RLS مفعّل على كل الجداول، والزائر يملك صلاحية **إضافة** فقط على جداول الطلبات (أعمدة محددة)، ودالة `newsletter_action`. في الخادم: middleware لحماية `/admin`، و zod، وفخ للبوتات (honeypot)، وسجل تدقيق. |
| **واجهات API** | `/api/admin/backup` و `/api/admin/export` و `/api/admin/file`، و server actions في `src/app/actions` و `src/app/admin/actions.ts`. كلها على الخادم المحلي فقط. |
| **معالجة الأخطاء** | `FormState` موحّد مع رسائل مترجمة، وصفحات 404 و error. |
| **اختبار موجود** | نوع المورد `QUIZ` في المكتبة المعرفية (`quizJson`): اختبار بسيط **تُرسل فيه الإجابات إلى المتصفح**. يبقى كما هو كمحتوى تعليمي مجاني، ولا يصلح أساسًا لنظام الاختبارات المحمي. |

### وظائف قابلة لإعادة الاستخدام
- جدول `Program` كأساس لـ «الدورة» (Course ID = `Program.id`).
- جدول `User` والأدوار وجلسات jose و bcrypt.
- `AuditLog` لتسجيل العمليات الحساسة وأحداث الحماية.
- `Notification` لتنبيه المدير.
- مكوّنات الواجهة: الهوية البصرية، العربية/الإنجليزية، RTL/LTR، النماذج، تبويبات الحساب.
- zod و `FormState` ونمط server actions.
- لوحة المدير: الهيكل والتنقل والصلاحيات.

## 2. التعارض الجوهري مع المتطلبات

**الموقع المنشور حاليًا ملفات ثابتة على GitHub Pages، بلا خادم.** الإيعاز يشترط أن يتم على الخادم كلٌّ من: بدء الاختبار، والتوقيت، وتقديم الأسئلة دون الإجابات، والتصحيح، والصلاحيات، و Rate Limiting، والروابط المؤقتة للملفات (الأقسام 10 و15 و23). كما أن لوحة المدير تعمل اليوم على جهازك فقط، **والمدرب يحتاج لوحة على الإنترنت**.

لهذا يلزم قرار في البنية قبل التنفيذ:

### الخيار (أ) — موصى به: نقل الموقع إلى استضافة تشغّل خادم Next.js
- الكود الحالي يعمل كما هو: النسخة الكاملة جاهزة بلوحة المدير والجلسات و server actions، ونشرها لا يحتاج إعادة بناء.
- كل منطق الاختبارات (التوقيت، التصحيح، تقديم الأسئلة، الصلاحيات) يُكتب في الخادم بـ TypeScript، وتبقى قاعدة البيانات Supabase نفسها.
- لوحات المدير والمدرب والمتدرب تصبح متاحة على الإنترنت.
- الملفات الحساسة تنتقل إلى **Supabase Storage خاص** بروابط مؤقتة.
- **التكلفة التقريبية:**
  - Railway: حوالي 5 دولارات شهريًا حسب الاستخدام (إعداد `railway.json` موجود في المشروع مسبقًا).
  - أو Vercel Pro: 20 دولارًا شهريًا (الخطة المجانية لا تسمح بالاستخدام التجاري).
- يُوحَّد دخول المتدربين على جدول `User`. لا توجد حسابات متدربين في Supabase Auth حاليًا (العدد صفر)، فلا شيء يحتاج إلى نقل.
- ينتقل الدومين `training.aldaleel.ly` لاحقًا إلى الاستضافة الجديدة بدل GitHub Pages.

### الخيار (ب): البقاء على GitHub Pages ونقل كل منطق الخادم إلى Supabase
- منطق الاختبارات يُكتب كدوال PostgreSQL (`SECURITY DEFINER`) و Edge Functions، والصلاحيات بـ RLS.
- يجب بناء **لوحة إدارة ثانية** للمدير والمدرب تعمل في المتصفح عبر Supabase، أي تكرار اللوحة الحالية، والإيعاز يمنع تكرار الأنظمة.
- عمل أكبر بكثير وصيانة أصعب، لأن المنطق موزّع بين SQL و Edge Functions والواجهة. لكن لا توجد استضافة إضافية (Supabase المجاني يكفي في البداية).

**التوصية: الخيار (أ).** فهو يحقق شرط «كل العمليات الحساسة على الخادم» بأقل تعقيد، ويعيد استخدام اللوحة والصلاحيات الموجودة بدل تكرارها.

## 4. الجداول المقترح إضافتها

لا تُحذف ولا تُعدَّل جداول قائمة، باستثناء إضافة أعمدة اختيارية.

| الجدول | الغرض |
|---|---|
| `CourseInstructor` | ربط المدرب بالدورة + صلاحيات مرنة: إنشاء اختبار، نشر مباشر، استيراد، تعديل، حذف، تصنيفات، سيناريوهات، نتائج، إعادة فتح محاولات. |
| `Enrollment` | قيد المتدرب في الدورة (يُنشأ من `Registration` المؤكَّد أو يدويًا). هو أساس «الاختبارات المسموح بها فقط». |
| `QuestionCategory` | تصنيف هرمي لكل دورة: Domain ← Topic ← Subtopic (عبر `parentId` و `kind`). |
| `Question` | السؤال: الدورة، النوع، النص عربي/إنجليزي، الدرجة، الوزن، الصعوبة، التصنيف، الكلمات المفتاحية، المرجع، الحالة، المنشئ، الإصدار، و `scenarioId` اختياري. |
| `QuestionVersion` | نسخة مجمّدة من السؤال (المحتوى + الإجابة + قواعد التقييم) تُربط بها المحاولات، فلا يُفسد تعديلُ السؤال لاحقًا المحاولاتِ السابقة. |
| `QuestionSecret` *(أو أعمدة منفصلة لا تُقرأ إلا من الخادم)* | الإجابات الصحيحة، قواعد التقييم، Feedback، Explanation، تفسير الخيارات. |
| `Scenario` | السيناريو متعدد الأسئلة كيان مستقل (عنوان، نص عربي/إنجليزي، بيانات المشروع، القيود، المخاطر، أصحاب المصلحة، المرفقات). |
| `QuestionAsset` | الصور والجداول والمرفقات، مخزنة في Supabase Storage **خاص**. |
| `ExamFolder` | المجلدات الفعلية لكل دورة: بنك الأسئلة، اختبارات المجالات، اختبارات محاكية، ويُسمح بأنواع إضافية لاحقًا. تُنشأ تلقائيًا مع كل دورة. |
| `Exam` | الاختبار وإعداداته: النوع (تدريبي/محاكي/نهائي)، المدة، المواعيد، المحاولات، الترتيب، الدرجة، النجاح، سياسات المراجعة والنتائج و Feedback، الحماية، السبورة، الحاسبة، الترجمة، والحالة (مسودة/منشور/موقوف/مؤرشف). |
| `ExamItem` / `ExamRule` | أسئلة مختارة يدويًا، أو قواعد سحب عشوائي (عدد من كل مجال/موضوع/صعوبة/نوع). |
| `ExamAttempt` | المحاولة: الحالة (In Progress, Submitted, Completed, Timed Out, Abandoned, Under Review)، أوقات الخادم، الدرجة، النسبة، العدّادات. |
| `AttemptQuestion` | الأسئلة المسحوبة لهذه المحاولة بالترتيب، مع إصدار السؤال وترتيب الخيارات. |
| `AttemptAnswer` | الإجابة، علامة المراجعة، الدرجة المحسوبة على الخادم، وتصحيح المقالي يدويًا. |
| `ProctorEvent` | أحداث الحماية: مغادرة الصفحة، فقدان التركيز، الخروج من ملء الشاشة، النسخ… مع الوقت والعدد. |
| `MistakeItem` / `MistakeReview` | سجل أخطاء المتدرب (سؤال واحد لكل متدرب، مع عدد مرات الخطأ والتواريخ والحالة) ومراجعاته. |
| `RateLimit` *(أو جدول عدّاد)* | تحديد معدل الطلبات لكل مستخدم أو محاولة. |

إضافة على جدول قائم: الدور `INSTRUCTOR` في `User.role`. وفي الخيار (أ) يُستكمل استخدام `Registration.userId` الموجود أصلًا.

**الأمان في قاعدة البيانات:** RLS مفعّل على كل الجداول الجديدة، ولا صلاحية لدوري `anon` و `authenticated` عليها إطلاقًا. القراءة والكتابة من الخادم فقط. المتصفح لا يتصل بجداول الاختبارات مباشرة أبدًا.

## 5. الملفات التي ستتأثر (الخيار أ)

- `prisma/schema.prisma`: الجداول الجديدة.
- `supabase/setup.sql`: قفل الجداول الجديدة.
- `src/lib/auth.ts` و `middleware.ts`: دور المدرب وحماية المسارات الجديدة.
- `src/app/admin/…`: أقسام جديدة: بنوك الأسئلة، الاختبارات، المحاولات، التقارير، الصلاحيات.
- `src/app/[locale]/account/…`: اختباراتي، اختبار الأخطاء، النتائج.
- **ملفات جديدة:**
  - `src/lib/exams/…`: التصحيح، السحب العشوائي، التوقيت، الاستيراد والتصدير.
  - `src/app/[locale]/exam/[attemptId]`: واجهة المحاكاة.
  - مكوّنات السبورة والحاسبة.
- `.github/workflows/pages.yml` و `scripts/prepare-static.mjs`: يُستبدلان بنشر الخادم، أو يبقى GitHub Pages كنسخة احتياطية مؤقتًا.
- إنشاء مجلدات الدورة تلقائيًا: يُستدعى عند إضافة دورة في `src/app/admin/actions.ts`، مع ترحيل لمرة واحدة ينشئها للدورات العشر الحالية.

## 6. المخاطر التقنية

1. **حجم المشروع كبير جدًا** (15 نوع سؤال، 5 صيغ استيراد، لوحات لثلاثة أدوار، محاكاة، حماية، تقارير). التنفيذ على مراحل، مع اختبار كل مرحلة قبل التالية كما يطلب الإيعاز.
2. **توحيد الهوية:** حسابات Supabase Auth الحالية مقابل جدول `User`. يجب اختيار نظام واحد للدخول دون فقد حسابات.
3. **التصحيح الآلي للأنواع المعقدة** (Hotspot، Drag & Drop، Cloze، Numerical بتسامح): قواعد التقييم تُحدَّد مسبقًا لكل نوع وتُختبر بحالات محددة.
4. **الاستيراد:** Moodle XML لا يدعم كل أنواعنا (مثل Hotspot المتقدم والسيناريو متعدد الأسئلة). سيُعرض في المعاينة ما لا تدعمه كل صيغة بدل ادعاء دعمه.
5. **حدود الحماية في المتصفح:** لا يمكن منع تصوير الشاشة أو التصوير بالهاتف 100٪. الحماية الفعلية هي عدم إرسال البيانات الحساسة أصلًا + الصلاحيات + الرصد + Watermark، وسيُوثَّق ذلك.
6. **الأداء:** محاكاة 180 سؤالًا مع حفظ تلقائي. تُحفظ الإجابات بطلبات صغيرة مع تجميعها لتقليل الضغط على قاعدة البيانات.
7. **النشر الإنتاجي:** أي تغيير على قاعدة البيانات الحية يسبقه نسخ احتياطي (`/api/admin/backup` موجود)، والجداول الجديدة إضافية فقط ولا تمس البيانات الحالية.

## 7. آلية حماية البيانات الحالية
- نسخة احتياطية كاملة قبل كل تغيير في قاعدة البيانات.
- تغييرات إضافية فقط: جداول جديدة وأعمدة اختيارية، دون حذف أو إعادة تسمية.
- `prisma db push` يُراجع قبل التطبيق، ولا يُقبل أي تحذير بفقد بيانات.
- اختبار التكامل بعد كل مرحلة: الدخول، طلبات التسجيل، المحتوى، لوحة المدير، الموقع العام.

1. **الاستضافة:** الخيار (أ) خادم Next.js (موصى به) أو الخيار (ب) البقاء على GitHub Pages مع Supabase.
2. **الترجمة:** الاكتفاء بالنص الإنجليزي المخزَّن (موصى به)، أو إضافة ترجمة آلية احتياطية بتكلفة.
3. **الحسابات:** تم التحقق: عدد حسابات المتدربين في Supabase Auth اليوم **صفر**. لذلك يمكن توحيد الدخول على نظام واحد دون نقل أي حساب. القرار المطلوب فقط هو اختيار الاستضافة.
