# نظام الاختبارات الإلكترونية — تقرير المرحلة 1: الأساس (الأدوار، القيد، مجلدات الدورات)

> القرار المعتمد: **الخيار (ب)**. يبقى الموقع على GitHub Pages، ويكون Supabase هو «الخادم».
> التاريخ: 2026-11-26

---

## البنية المعتمدة للخيار (ب)

```
المتصفح (الموقع الثابت على GitHub Pages)
   │  تسجيل الدخول: Supabase Auth (المدير والمدرب والمتدرب)
   │  الطلبات: supabase.rpc('exam_…') فقط، ولا قراءة مباشرة لأي جدول
   ▼
Supabase PostgreSQL
   ├─ دوال exam_* (SECURITY DEFINER): هي «الخادم». تتحقق من الجلسة والدور وصلاحيات الدورة،
   │   وتعيد البيانات المسموح بها فقط. ستتولى لاحقًا التوقيت والتصحيح وتقديم الأسئلة دون إجابات.
   ├─ جداول الاختبارات: RLS مفعّل، ولا صلاحية لدوري anon و authenticated عليها إطلاقًا
   └─ Storage خاص (في مرحلة لاحقة) لصور الأسئلة ومرفقاتها، مع سياسات وصول وروابط مؤقتة
```

- **لا تكرار للوحة الإدارة:** لوحة الإدارة الحالية (على جهازك) تبقى لمحتوى الموقع. إدارة الاختبارات (بنوك الأسئلة، الاختبارات، المحاولات، التقارير) ستكون **صفحات جديدة على الموقع المنشور** يستخدمها المدير والمدرب بحساب Supabase. لا يوجد نظام سابق لإدارة الاختبارات، فهذه الصفحات ليست تكرارًا لشيء موجود.
- **الترجمة:** النص الإنجليزي يُخزَّن مع كل سؤال (بلا تكلفة). الترجمة الآلية الاحتياطية تبقى اختيارية، ولن تُفعَّل دون موافقتك على التكلفة.

## 1. ما الذي تم فحصه؟
- بنية جدول الدورات `Program` ومعرّفاتها (10 دورات).
- نظام الدخول في الموقع المنشور (Supabase Auth): عدد الحسابات حاليًا **صفر**.
- صلاحيات Supabase الحالية (`supabase/setup.sql`)، للتأكد أن الإضافة لا تفتح شيئًا للزوار.
- عدد السجلات في كل جدول قبل التغيير (لقطة للمقارنة).

## 2. ما الذي تم تنفيذه؟

| الجدول الجديد | الغرض |
|---|---|
| `ExamMember` | ربط حساب Supabase بدور: `ADMIN` أو `INSTRUCTOR` أو `LEARNER`. يُنشأ تلقائيًا كمتدرب عند أول دخول. |
| `CourseInstructor` | تعيين مدرب لدورة مع **13 صلاحية مرنة** (القسم 17.5): تعديل الأسئلة، حذفها، التصنيفات، السيناريوهات، الاستيراد، التصدير، إنشاء الاختبارات، النشر المباشر أو اشتراط موافقة المدير، اختبارات المجالات، المحاكاة، النتائج، تصحيح المقالي، إعادة فتح المحاولات. |
| `Enrollment` | قيد المتدرب في الدورة (نشط / موقوف / مكتمل)، مع ربط اختياري بطلب التسجيل. |
| `ExamFolder` | **المجلدات الفعلية لكل دورة**: بنك الأسئلة، اختبارات المجالات، اختبارات محاكية للامتحان، اختبار الأخطاء، النتائج والتقارير. لكل مجلد معرّف وارتباط بالدورة واسم ونوع وحالة وتاريخ. يمكن إضافة مجلدات أخرى لاحقًا (`CUSTOM`). |
| `ExamAuditLog` | سجل للعمليات الحساسة: من فعل ماذا ومتى. |

| الدالة | من يستطيع استدعاءها | ماذا تفعل |
|---|---|---|
| `exam_me` | أي مستخدم مسجّل الدخول | تسجّله عند أول دخول، وتعيد دوره والدورات المسموح له بها فقط |
| `exam_course_folders` | من له علاقة بالدورة | المدير والمدرب يرون المجلدات الخمسة. **المتدرب لا يرى بنك الأسئلة إطلاقًا** |
| `exam_course_people` | المدير، أو مدرب الدورة إن كانت لديه صلاحية النتائج | مدربو الدورة ومتدربوها |
| `exam_admin_members` / `exam_admin_set_role` | المدير فقط | قائمة الأعضاء وتغيير الأدوار (مع منع حذف آخر مدير) |
| `exam_admin_assign_instructor` / `exam_admin_remove_instructor` | المدير فقط | تعيين مدرب لدورة بصلاحياته، أو إزالته |
| `exam_admin_enroll` | المدير فقط | قيد متدرب في دورة أو تغيير حالة القيد |

- **إنشاء المجلدات تلقائيًا:** trigger على جدول الدورات. أي دورة جديدة تُضاف من لوحة الإدارة تحصل فورًا على مجلداتها الخمسة، دون أي برمجة إضافية. والدورات العشر الحالية حصلت على مجلداتها (50 مجلدًا).

## 3. الملفات التي تم تعديلها
- `prisma/schema.prisma`: الجداول الخمسة الجديدة وعلاقاتها بالدورات. ونوع قاعدة البيانات صار PostgreSQL، لأن المشروع يعمل على Supabase.
- `supabase/exams.sql` *(جديد)*: الـ trigger، والدوال، وقفل الجداول، والصلاحيات.
- `scripts/supabase-setup.ts`: يطبّق `exams.sql` بعد `setup.sql`.
- `scripts/test-exams-phase1.mjs` *(جديد)*: اختبارات المرحلة.

## 4. الجداول والسياسات المضافة
- RLS مفعّل على الجداول الخمسة الجديدة، ولا صلاحية لدوري `anon` و `authenticated` عليها.
- الدوال المساعدة الداخلية (`exam_current_member`، `exam_course_access`، `exam_instructor_can`، `exam_log`…) **غير قابلة للاستدعاء من المتصفح**.
- 8 دوال فقط متاحة للمستخدم المسجّل، ولا شيء للزائر غير المسجّل.

## 5. الوظائف التي تم اختبارها ونتائجها

**اختبارات وظيفية: 22 من 22 نجحت.** نُفّذت على قاعدة البيانات الحقيقية داخل معاملة أُلغيت في النهاية، فلم تبقَ أي بيانات تجريبية.

| قيد بريد غير مسجّل → رفض واضح | ✔ |

| مدرب PMP يحاول فتح CAPM → رفض | ✔ |

| لا بيانات تجريبية متبقية | ✔ |

**اختبارات من جهة المتصفح** (بمفتاح الموقع العام عبر Supabase API الحقيقي):
- قراءة الجداول الخمسة مباشرة → **مرفوضة** (404) ✔
- استدعاء `exam_me` و `exam_admin_members` بدون دخول → **مرفوض** (401) ✔
- استدعاء دالة داخلية (`exam_current_member`) → **مرفوض** ✔
- فحص الصلاحيات في قاعدة البيانات: لا صلاحية جداول لـ `anon` ولا لـ `authenticated` ✔

**التكامل مع الموقع الحالي:**
- عدد السجلات بعد التغيير مطابق لما قبله: 10 دورات، 7 أسئلة شائعة، 6 موارد، 6 إعدادات، مستخدم واحد. ورقم الهاتف المعدّل ما زال كما هو ✔
- النسخة الكاملة (الخادم المحلي) تُبنى وتعمل، ولوحة الإدارة تفتح ✔
- النسخة الثابتة تُبنى في GitHub Actions وتُنشر بنجاح، والموقع المنشور يعمل ✔

## 7. ما زال غير مكتمل في هذه المرحلة
- **لا توجد واجهة بعد:** إدارة الأدوار والقيد تتم حاليًا عبر الدوال فقط. واجهتها ستُبنى مع لوحة إدارة الاختبارات في المرحلة 2، كي لا تكون واجهة شكلية بلا وظيفة.
- **أول مدير للاختبارات:** يجب أن تنشئ حسابًا على الموقع المنشور (صفحة «إنشاء حساب») ثم تخبرني بالبريد، فأمنحه دور المدير من جهة الخادم. لا تُمنح هذه الصلاحية من المتصفح إطلاقًا.
